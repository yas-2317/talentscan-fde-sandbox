## Componentを読む単位

本日は、Componentを次の4つへ分けて確認した。

| 区分 | `FdeRoadmap`で確認するもの |
|---|---|
| Componentの入口 | `export function FdeRoadmap(...)` |
| 入力 | ComponentがPropsとして直接受け取る`progress` |
| 内部処理 | `progress`を使った`map()`、`filter()`、進捗率の計算など |
| 出力 | `return (...)`が直接返すJSX |

ここでいうJSXは、React Componentが画面構造を表現するために返す値である。JSXがそのまま画面上のRoadmapなのではなく、Reactが後続でJSXを使って描画した結果がRoadmapとして見える。

## 理解確認1：Componentの直接の入力

**対象：**

```tsx
export function FdeRoadmap({ progress }: { progress: Progress }) {
```

**質問：** `FdeRoadmap` Componentが直接受け取っている入力は何か。

**本人回答：**

```text
progress
```

**評価：正解。**

Componentが直接受け取る入力として`progress`を特定できた。

## 理解確認2：`filter()`の入力・処理・出力

**対象：**

```tsx
const chapters = progress.chapters.filter(
  (chapter) => chapter.phase === phase.id
);
```

**最初の本人回答：**

```text
入力：chapter

処理：
chapterの入力内容をchapter.phaseに変換し、
phase.idを付与する

出力：
chapterのProgress情報
```

**評価：概念理解不足。**

次の3点が混在していた。

- `chapter`は、`filter()`が配列の要素を1件ずつ判定するときの一時変数であり、処理全体への入力ではない。
- `filter()`は要素を変換したり`phase.id`を付与したりせず、条件に一致する要素だけを残す。
- 出力はProgress情報ではなく、条件に一致した`chapter`だけを含む新しい配列である。

**再回答：**

```text
入力：
progress.chapters の配列
判定に使う phase.id

処理：
progress.chapters の各 chapter について、
chapter.phase === phase.id が true か判定し、
true の chapter だけを残す

出力：
条件に一致した chapter だけを含む新しい配列
```

**評価：正解。**

一度修正した後は、`filter()`が直接参照するもの、行う判定、直後に返す新しい配列を正しく切り分けられた。

## 理解確認3：Component関数自身の出力

**対象：**

```tsx
export function FdeRoadmap({ progress }: { progress: Progress }) {
  return (
    <div className="roadmap">
      ...
    </div>
  );
}
```

**固定条件：**

```text
FdeRoadmap関数自身が直接返すものだけを答える。
Reactによる後続のブラウザ描画は含めない。
```

**本人回答：**

```text
出力：Roadmap
理由：
```

**評価：概念理解不足。**

`FdeRoadmap`自身が直接返すものはJSXである。Roadmapは、そのJSXが後続のReact処理によって描画されたときの画面上の意味・見た目であり、関数自身の直接の出力ではない。

正しい境界は次のとおり。

```text
FdeRoadmap()
↓ 直接の出力
JSX
↓ ReactがJSXを使って描画
Roadmapとして画面に見える
```

## 本日の重要な気づき

本人から、次の課題が明示された。

```text
コードの内容が変わると、
入力・処理・出力の切り分け基準が崩れる
```

`filter()`やComponent関数のように分析対象が変わると、次の判断が安定していない。

- 何を処理全体への入力と見るか。
- 関数内部で使う一時変数と、処理全体への入力をどう分けるか。
- どこまでを対象の処理自身の役割とするか。
- 直接の出力と、後続工程による最終結果をどう分けるか。

個別の関数名や構文を覚えるだけでなく、最初に「今回どの処理を1単位として分析するか」を決める練習が必要である。

## 入力・処理・出力の基本手順

今後は、コードの種類にかかわらず次の順序で確認する。

```text
1. 分析対象の処理単位を決める
2. その処理が直接受け取る・参照するものを特定する
3. その処理自身が何をしているか説明する
4. その処理が直後に返すものを特定する
5. 後続処理を切り捨てる
```

本日の例では、`filter()`と`FdeRoadmap()`を別々の処理単位として扱う。

| 分析対象 | 入力・参照 | 処理 | 直後の出力 |
|---|---|---|---|
| `filter()` | `progress.chapters`、判定に使う`phase.id` | 各要素が条件に一致するか判定し、一致する要素だけを残す | 新しい配列 |
| `FdeRoadmap()` | Propsとして受け取る`progress` | `progress`から画面構造を組み立てる | JSX |
