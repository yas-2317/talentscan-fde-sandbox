## `FdeRoadmap`の役割

確認した定義は次のとおり。

```tsx
export function FdeRoadmap({ progress }: { progress: Progress }) {
  return (
    // JSX
  );
}
```

実コードから役割を整理した。

| 種類 | 今回確認した内容 |
|---|---|
| Component | `FdeRoadmap`。Propsを受け取り、JSXを返すReact Component。 |
| Props | `progress`。`page.tsx`から渡されるロードマップ用データ。 |
| State | このComponent内にはない。 |
| Event | このComponent内にはない。 |

本人は当初、データ種別を「関数」、処理を「export」と回答した。

**評価：**

- 「関数」は部分的に正しいが、ここではJSXを返すReact Componentとして使われている。
- `export`は別ファイルから利用可能にする仕組みであり、表示データに対する処理ではない。
- 誤答の中心は、React Componentの役割と`export`の役割の混同だった。

## `FdeRoadmap`内の処理

実コード上で次の処理を確認した。

```text
progress.phasesをmapする
↓
phaseごとにprogress.chaptersをfilterする
↓
完了章数と全章数から進捗率を計算する
↓
chaptersをmapしてWeekごとのJSXを生成する
↓
statusによってリンクやステータス表示を切り替える
```

入力・処理・出力へ分けると次のようになる。

| 区分 | 内容 |
|---|---|
| 入力 | `progress` Props。 |
| 処理 | PhaseごとにChapterを抽出し、進捗率と状態別表示を計算する。 |
| 出力 | Phase、章数、進捗バー、Week、タイトル、完了・学習中ステータスを含むJSX。 |

`map`や`filter`は、ここでも受け取ったデータをメモリ上で加工する処理であり、DB保存ではない。

## `import type`と`ReturnType`

`components/fde-roadmap.tsx`では次のコードを確認した。

```ts
import type { getLearningProgress } from "@/lib/learning-roadmap";

type Progress = ReturnType<typeof getLearningProgress>;
```

今回理解したことは次のとおり。

- `import type`は、実行時に`getLearningProgress`を呼ぶためのimportではない。
- `ReturnType`により、`getLearningProgress`の戻り値と同じ構造を`Progress`型として利用している。
- 実データは`progress` Propsとして`page.tsx`から渡される。

```text
型の参照
→ import typeとReturnType

実データの受け渡し
→ <FdeRoadmap progress={progress} />
```

## 学習ログの取得元

`lib/learning-logs.ts`では、学習ログの保存場所を次のように指定している。

```ts
const logsDirectory = path.join(process.cwd(), "docs", "learning-log");
```

各日付のMarkdownは、Node.jsの`fs`で読み込まれる。

```ts
const source = await fs.readFile(
  path.join(logsDirectory, `${date}.md`),
  "utf8",
);
```

確認した範囲を整理すると次のとおり。

| 項目 | 確認結果 |
|---|---|
| 元データ | `docs/learning-log/YYYY-MM-DD.md` |
| 取得方法 | Node.jsの`fs`によるファイル読み込み |
| 変換 | Markdownとfrontmatterを`LearningLog`型へ変換 |
| API通信 | 確認した経路ではなし |
| DB取得・保存 | 確認した経路ではなし |

`lib/learning-logs.ts`が学習データそのものを直接保持しているわけではない。Markdownファイルを読み込み、画面や進捗計算で扱える`LearningLog[]`へ変換している。

## `getLearningProgress(logs)`の役割

`app/learning/page.tsx`では、取得したログを次の関数へ渡している。

```ts
const progress = getLearningProgress(logs);
```

`lib/learning-roadmap.ts`で確認した処理は次のとおり。

```text
logsから完了済みLessonのslugを抽出
↓
最初の未完了Chapterを特定
↓
Chapterごとの完了Lesson数を計算
↓
completed・current・upcomingを判定
↓
進捗情報を追加したオブジェクトを返す
```

ここではDB更新や永続保存をしていない。受け取った`logs`をメモリ上で加工し、ロードマップ表示に使う`progress`オブジェクトを返している。

## 理解確認と本人回答

### 問1：`Promise.all`を使う理由

**対象コード：**

```ts
const [logs, readings] = await Promise.all([
  getLearningLogs(),
  getReadings(),
]);
```

**本人回答：**

```text
最新ログと次に再開する教材をもとに画面表示用の値を作るため、
同時に取得している
```

**評価：** 取得目的と同時取得については理解できている。

説明に不足していたのは、2つの処理が互いに依存せず、順番に待つ必要がない点である。

```text
getLearningLogs()とgetReadings()は互いに依存しない
↓
Promise.allで同時に開始する
↓
両方の完了を待つ
```

概念の誤答ではなく、説明の粒度不足として記録する。

### 問2：`getLearningProgress(logs)`の入力・処理・出力

**本人回答：**

```text
入力：Learningprogress
処理：学習進捗を取得
出力：フェーズ・進捗・ステータスの表示
```

**評価：** 関数の目的は概ね理解しているが、入力変数と出力の整理に修正が必要だった。

| 区分 | 正確な整理 |
|---|---|
| 入力 | `LearningLog[]`型の`logs` |
| 処理 | ログから完了済みLessonを抽出し、Chapterごとの完了数と進捗ステータスを計算する |
| 出力 | ロードマップ表示に使う`progress`オブジェクト |

関数は画面を直接表示しない。戻された`progress`を、その後の`FdeRoadmap`がJSXへ変換する。

```text
誤答分類
→ 入力変数の取り違え
→ 関数出力と画面表示の混同
```

### 問3：StateやEventがない場合のReact利用

**本人回答：**

```text
いいえ

それら二つが存在しなくとも、
Component／Propsが存在すればReactが使われている
```

**評価：** 正解。

StateやEventはReact利用の必須条件ではない。`LearningPage`や`FdeRoadmap`がJSXを返すComponentであることが、Reactを使っている根拠になる。PropsもすべてのComponentに必須ではない点を補足した。

## 本日の理解上の変化

学習開始時点では、import元や`map`対象を概念上は判断できていたが、実ファイル間の経路は未確認だった。また、関数の戻り値とComponentによる画面表示が混在していた。

実ファイル確認後は、次をコード上で分けて説明できるようになった。

- Markdownが学習ログの元データである。
- `getLearningLogs()`がMarkdownを読み、`LearningLog[]`へ変換する。
- `getLearningProgress(logs)`がログをメモリ上で加工し、`progress`を返す。
- `page.tsx`が`progress`をPropsとして渡す。
- `FdeRoadmap`がPropsをJSXへ変換し、ロードマップを表示する。
- `export`はデータ加工ではなく、別ファイルから利用可能にする仕組みである。
- `import type`は型の参照であり、実データの取得ではない。
