# 2026-07-28｜Reactのcomponent・props・state

## 学習時間

60分。

## 今日の到達点

- Reactのcomponent、props、state、eventを区別できた。
- チェックボックス操作から表示更新までを、event、state、再実行、表示更新の順で説明できた。
- props、state、計算された表示結果を別のものとして読めた。
- 画面上だけの絞り込みにDB保存が必要か判断できた。

## 学習に使ったComponent

候補者一覧で「評価済みのみ表示」を切り替えるComponentを読んだ。

```tsx
"use client";

import { useState } from "react";

type CandidateStatus = "pending" | "completed";

type Candidate = {
  id: number;
  name: string;
  status: CandidateStatus;
};

type CandidateListProps = {
  candidates: Candidate[];
};

export function CandidateList({ candidates }: CandidateListProps) {
  const [showCompletedOnly, setShowCompletedOnly] = useState(false);

  const visibleCandidates = showCompletedOnly
    ? candidates.filter(
        (candidate) => candidate.status === "completed"
      )
    : candidates;

  return (
    <section>
      <label>
        <input
          type="checkbox"
          checked={showCompletedOnly}
          onChange={(event) =>
            setShowCompletedOnly(event.target.checked)
          }
        />
        評価済みのみ表示
      </label>

      <ul>
        {visibleCandidates.map((candidate) => (
          <li key={candidate.id}>{candidate.name}</li>
        ))}
      </ul>
    </section>
  );
}
```

## component・props・state・event

| 概念 | 今回のコードでの役割 |
|---|---|
| component | JSXを返す画面部品。今回は`CandidateList`。 |
| props | 親Componentから渡される外部入力。今回は候補者一覧の`candidates`。 |
| state | Component内部で実行中に覚えている現在値。今回は`showCompletedOnly`。 |
| event | 利用者の操作によって発生する出来事。今回はチェックボックスの`onChange`。 |

propsには候補者データだけでなく、文字列、数値、関数なども渡せる。propsは「外から受け取る」という役割を表し、stateは「内部で現在値を覚える」という役割を表す。

## props・state・表示結果の関係

今回のコードは、次の3つへ分けて読める。

```text
props:
親Componentから渡される候補者一覧

state:
評価済みだけ表示する設定がONかOFFか

visibleCandidates:
propsとstateから計算された、実際に表示する候補者一覧
```

`visibleCandidates`はstateではない。propsの`candidates`とstateの`showCompletedOnly`から、Componentが実行されるたびに計算する表示用データである。

最終的な整理は次のとおり。

```text
props:
外から渡される値

state:
Component内部で覚えている現在値

表示結果:
propsとstateを使って計算されるもの
```

## 理解がどう変わったか

当初は、propsとstateを次のように捉えていた。

**本人回答：**

- `props: componentから渡される入力（対象となるデータ？）`
- `state: 入力から特定の状態のデータを抽出する`
- `ってイメージなんだけど、一般的な定義ではない気がする`

propsは概ね合っていたが、stateを抽出後のデータと捉えていた点を修正した。抽出条件として使う現在値が`showCompletedOnly`、抽出結果が`visibleCandidates`である。

その後、次のように説明を更新した。

**本人回答：**

`propsは親componentから受け取る入力、Stateは画面上での動きを短期的に記憶するためのものって感じか`

「画面上での動き」そのものではなく、画面操作の結果として変化した現在値を覚える、と補足した。通常のstateは実行中のブラウザメモリ上にあり、リロードやページ移動で初期化される場合がある。

## チェックボックスから表示更新まで

```text
チェックボックスを操作
↓
onChange eventが発生
↓
event.target.checkedを受け取る
↓
setShowCompletedOnlyでstateを更新
↓
Componentが新しいstateで再実行される
↓
visibleCandidatesを再計算
↓
評価済み候補者だけを表示
```

再実行時には、次の条件がもう一度評価される。

```tsx
const visibleCandidates = showCompletedOnly
  ? candidates.filter(
      (candidate) => candidate.status === "completed"
    )
  : candidates;
```

stateが`true`なら`filter`を実行し、`false`なら元の`candidates`を表示対象にする。

## stateとソースファイル

```tsx
const [showCompletedOnly, setShowCompletedOnly] = useState(false);
```

`false`は初期値である。チェックボックスを操作しても、ソースファイル上の`useState(false)`が`useState(true)`へ書き換わるわけではない。

変わるのは、ブラウザ上で実行中のstateである。リロードすると、通常はファイルに書かれた初期値から再開する。

## stateとDB保存

「評価済みのみ表示」は、候補者の`status`や`score`を書き換えず、既存データの表示対象だけを切り替える。

```text
候補者のDBデータ
→ 変更しない

ブラウザ上の表示条件
→ stateでON・OFFを切り替える
```

そのため、原則としてAPI通信やDB保存は不要である。表示設定を次回も維持する要件がある場合は、URL、ブラウザストレージ、DBなどへの保存を別途検討する。

## 理解確認と本人回答

### 理解確認1：propsとstateの違い

**本人の初回回答：**

- `props: componentから渡される入力（対象となるデータ？）`
- `state: 入力から特定の状態のデータを抽出する`
- `ってイメージなんだけど、一般的な定義ではない気がする`

**評価：**

- propsは概ね正解。
- stateは修正が必要。
- state自体は抽出後のデータではなく、抽出条件などに使う現在値。
- stateの`showCompletedOnly`と、抽出結果の`visibleCandidates`を区別した。

**本人の理解更新：**

`propsは親componentから受け取る入力、Stateは画面上での動きを短期的に記憶するためのものって感じか`

**補足後の整理：**

- propsは親Componentから渡される入力。
- stateはComponent内部で実行中に覚えている現在値。
- 表示結果はpropsとstateから計算される。

### 理解確認2：eventから表示更新まで

**本人回答：**

```text
チェックボックス操作
→ event発生
→ setShowCompletedOnly(true)
→ stateがtrueになる
→ Componentが再実行される
→ 評価済みだけ表示される
```

**評価：** 正解。

**補足：** Componentの再実行時に`visibleCandidates`が再計算され、評価済み候補者だけが表示される。

### 理解確認3：DB保存が原則不要な理由

**本人回答：**

`DB内の情報を変更する操作は発生しないため`

**評価：** 正解。

**補足：** 候補者データを変更せず、ブラウザ上で表示対象だけを切り替えている。

## 今日の重要な修正点

- stateは、特定の状態のデータを抽出した結果ではない。
- stateは、抽出条件や画面設定として使われる現在値になり得る。
- `visibleCandidates`はstateではなく、propsとstateから計算された値である。
- 画面操作でソースファイルの`useState(false)`が書き換わるわけではない。
- propsは外部から受け取る値、stateは内部で覚えている現在値である。
- stateの変更とDBデータの変更は別である。
- 一時的な表示条件だけなら、API通信やDB保存は原則不要である。

## 今日説明できるようになったこと

候補者一覧はpropsとして親Componentから渡され、「評価済みのみ表示」のON・OFFはstateとしてComponent内部に保持される。チェックボックスのeventでstateが変わるとComponentが再実行され、propsと新しいstateから`visibleCandidates`が再計算されて画面が更新される。この操作は候補者データ自体を変更しないため、原則としてDB保存は不要と判断できる。
