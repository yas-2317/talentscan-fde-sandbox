# 2026-07-25｜Git Branch・merge・安全な開発フロー

## 今日の到達点

- Branchを使って作業中の変更をmainから分離できた。
- 作業BranchをGitHubへpushし、mainにはまだ影響しないことを確認した。
- 取り込み先のmainへ移動してからmergeする流れを実践した。
- Fast-forward mergeと、merge後にmainをpushする理由を説明できた。

## Branchとmainの役割

| Branch | 役割 |
|---|---|
| `main` | 動作確認済みで、基本的に公開可能なコードを置く。 |
| 作業Branch | mainへ直接影響を与えず、変更を進めて確認する。 |

複数人やCodexなどのAIエージェントが同時にmainを直接変更すると、作業がぶつかる可能性がある。Branchを分ければ、それぞれが独立して作業し、完成後にmainへ取り込める。

```text
main
├── feature/practice
├── feature/dashboard
└── feature/candidate-list
```

## 今回実践した全体の流れ

```text
main
↓
git switch -c feature/practice
↓
作業Branch上で変更
↓
git status・git diff
↓
git add・git commit
↓
git push -u origin feature/practice
↓
GitHubで作業Branchを確認
↓
git switch main
↓
git merge feature/practice
↓
git push
↓
GitHubのmain更新
↓
Vercel自動デプロイ
```

作業時のBranch名は、手元の説明にあった`feature/practice-branch`ではなく、Git履歴で確認できた`feature/practice`である。

## Branchの作成と現在地の確認

```bash
git switch -c feature/practice
```

| 部分 | 意味 |
|---|---|
| `git switch` | 移動するBranchを指定する。 |
| `-c` | 新しいBranchを作成する。 |
| `feature/practice` | 今回作成したBranch名。 |

作成後は、次のコマンドで現在地を確認した。

```bash
git branch
```

現在いるBranchには`*`が付く。

```text
* feature/practice
  main
```

## 作業Branchでの変更とcommit

作業Branch上で、学習ポータルの表示を英語へ変更した。commit `356c29d`（`translation`）では、次の2ファイルが変更されている。

- `app/learning/layout.tsx`
- `app/learning/page.tsx`

ナビゲーションの`aria-label`、ダッシュボードの統計ラベル、学習ログ、ロードマップなどの表示を英語へ変更した。

```bash
git status
git diff
git add <対象ファイル>
git commit -m "translation"
```

| コマンド | 確認・変更すること |
|---|---|
| `git status` | 変更されたファイルと、commit対象の状態を確認する。 |
| `git diff` | 変更した行と、意図しない差分がないかを確認する。 |
| `git add <対象ファイル>` | 次のcommitへ含める変更を選ぶ。 |
| `git commit` | 現在のBranchの履歴として変更を確定する。 |

commitは作成したBranchに属する。この時点では、mainの履歴は変わらない。

## `git diff`の表示から抜ける

差分が長いときはページャーが開き、画面下部に`(END)`と表示されることがある。

| キー | 操作 |
|---|---|
| `Space` | 次のページ |
| `b` | 前のページ |
| `j`または`↓` | 1行下 |
| `k`または`↑` | 1行上 |
| `q` | 終了 |

`q`は`quit`の意味で、今回`git diff`の表示から抜ける方法として確認した。

## 作業BranchをGitHubへpush

```bash
git push -u origin feature/practice
```

| 部分 | 意味 |
|---|---|
| `git push` | ローカルのcommitをGitHubへ送る。 |
| `origin` | 接続先として登録されたGitHubリポジトリ。 |
| `feature/practice` | GitHubへ送るBranch。 |
| `-u` | ローカルBranchとGitHub上のBranchの対応関係を設定する。 |

`-u`でupstreamを設定すると、同じBranchでは次回から`git push`だけで送れる。実際にローカルの`feature/practice`は、GitHub上の`origin/feature/practice`を追跡している。

この時点では、次のように変更が分離されていた。

```text
feature/practice → 変更あり
main             → 変更なし
```

## mainへのmerge

merge前に`git status`で作業ツリーがきれいであることを確認し、mainへ移動した。

```bash
git switch main
git merge feature/practice
```

mergeは、別のBranchの変更履歴を現在のBranchへ取り込む操作である。今回はmainへ取り込むため、先に`git switch main`を実行した。

```text
feature/practice
↓
git switch main
↓
git merge feature/practice
↓
mainへ変更を取り込む
```

Git履歴では、mainが`2c47fc5`から作業Branchの`356c29d`までFast-forwardしている。Fast-forwardは、main側に別の新しい変更がなく、Branchの履歴までそのまま前進できた状態である。

## merge後のpushと公開

ローカルでmergeしただけでは、GitHub上のmainは更新されない。

```bash
git push
```

mainをpushするとGitHubのmainが更新され、このリポジトリではVercelの自動デプロイが始まる。

merge後には、`Days of Llearning`を`Days of Learning`へ直す誤字修正もmain上でcommit `eee4614`（`typo`）として追加されていた。現在のGitHub mainはこのcommitまで反映済みで、Vercelのデプロイ成功も確認できた。

公開サイト：<https://talentscan-fde-sandbox.vercel.app/learning>

## 今日使った主なコマンド

```bash
git branch
git switch -c feature/practice
git status
git diff
git add <対象ファイル>
git commit -m "translation"
git push -u origin feature/practice
git switch main
git merge feature/practice
git push
```

重要なのはコマンドの暗記ではなく、「Branchを作る、変更を確認する、履歴を作る、GitHubへ共有する、mainへ取り込む」という順番である。

## 今日説明できるようになったこと

Branchは、mainへ直接影響を与えずに変更を進める作業場所である。作業Branchでcommit・pushしてもmainは変わらない。変更を確認した後、取り込み先のmainへ移動してmergeし、mainをpushすることでGitHubとVercelへ反映される。
