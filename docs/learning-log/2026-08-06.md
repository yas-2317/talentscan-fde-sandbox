## 本日扱った教材サンプル

```ts
const response = await fetch("/api/candidates");

if (!response.ok) {
  throw new Error("候補者の取得に失敗しました");
}

const candidates = await response.json();
```

このコードを次の3段階に分けた。

```text
1. APIへHTTP GETリクエストを送る
2. HTTPステータスが成功範囲か判定する
3. レスポンス本文のJSONをJavaScriptの値へ変換する
```

## `fetch()`の役割

```ts
const response = await fetch("/api/candidates");
```

| 区分 | 内容 |
|---|---|
| 入力 | APIのURL`/api/candidates` |
| 処理 | URLへHTTP GETリクエストを送り、レスポンスが返るまで待つ。 |
| 直後の出力 | HTTP通信の結果を保持する`Response`オブジェクト |

HTTPメソッドを指定していないため、この教材サンプルの`fetch()`はGETリクエストを送る。

この時点の`response`は候補者配列そのものではない。レスポンス本文に加え、HTTPステータスやヘッダーなどを扱う`Response`オブジェクトである。

## `response.ok`と`throw`の役割

```ts
if (!response.ok) {
  throw new Error("候補者の取得に失敗しました");
}
```

`response.ok`は、HTTPステータスが200〜299なら`true`、404や500などでは`false`になるbooleanである。

| 対象 | 役割 |
|---|---|
| `response.ok` | HTTPステータスが成功範囲かをbooleanで示す。 |
| `!response.ok` | 成功ではない場合に`true`となり、`if`文の中へ進ませる。 |
| `throw new Error()` | 通常処理をその場で中断し、エラーを呼び出し元へ伝える。 |

`throw`はエラーメッセージを通常の戻り値として返す処理ではない。エラーを投げた時点で後続の通常処理へ進まなくなる。

## `response.json()`の役割

```ts
const candidates = await response.json();
```

| 区分 | 内容 |
|---|---|
| 入力 | `Response`オブジェクトの本文に含まれるJSON |
| 処理 | JSONをJavaScriptで扱える値へ変換する。 |
| 直後の出力 | 候補者情報を表すJavaScriptの配列またはオブジェクト |

変換方向は次のとおり。

```text
JSON
↓ response.json()
JavaScriptの配列・オブジェクト
```

JavaScriptのオブジェクトをJSONへ変換する処理ではない。

## データが画面へ表示されるまで

APIから返ったJSONが、そのまま画面へ表示されるわけではない。

```text
API
↓ JSONを含むHTTPレスポンス
fetch()
↓ Responseオブジェクト
response.json()
↓ JavaScriptの値
JSX
↓ 画面構造
ブラウザ
↓
画面を描画
```

各工程の直後の出力は異なる。全体を「候補者を取得して表示する処理」と説明できても、コード読解では`Response`、JavaScriptの値、JSX、ブラウザ描画の境界を分ける必要がある。

## 理解確認と本人回答

### 問1：`fetch()`の入力・処理・出力

**対象コード：**

```ts
const response = await fetch("/api/candidates");
```

**本人回答：**

```text
入力：/api/candidates
処理：APIを呼び出し、Candidate
出力：responce
```

**評価：**

- 入力となるAPIのURLは正しく特定できた。
- APIを呼び出す処理であることは理解できている。
- `fetch()`の時点で候補者データをJavaScriptの値として取得すると混同しかけた。
- 出力が`response`であることは理解できている。
- `responce`は表記上の誤りで、正しくは`response`。概念理解の誤りとは区別する。

**正確な整理：**

```text
入力：/api/candidates
処理：APIへHTTP GETリクエストを送り、レスポンスを待つ
出力：Responseオブジェクト
```

### 問2：404の場合に`response.json()`が実行されるか

**前提：**

```text
HTTPステータス：404
response.ok：false
```

**本人回答：**

```text
実行されない

404エラーが起こった時点で
「候補者の取得に失敗しました」が返ってくるから
```

**評価：** `response.json()`が実行されないという結論は正解。

404というステータスだけでJavaScriptの処理が自動的に止まるわけではない。`response.ok`が`false`となり、`throw`が実行されることで処理が中断される。また、エラーメッセージは通常の値として返るのではなく、エラーとして投げられる。

```text
HTTPステータスが404
↓
response.okがfalse
↓
!response.okがtrue
↓
throw new Error(...)を実行
↓
通常処理を中断
↓
response.json()は実行されない
```

### 問3：`response`と`candidates`の違い

当初の設問では回答対象が明確ではなく、本人から「これは何を答えればいいのか」と指摘があった。そこで、「それぞれの変数に何が入っているか」を答える設問へ修正した。

**正確な整理：**

| 変数 | 入っているもの |
|---|---|
| `response` | HTTP通信の結果を保持する`Response`オブジェクト |
| `candidates` | レスポンス本文のJSONを変換したJavaScriptの配列またはオブジェクト |

当初の問3は本人の誤答として扱わない。

## 本人の理解上の課題

本人から次の自己認識が示された。

```text
入力・処理・出力の流れの切り分けを、
以前から十分に理解し切れていない
```

全体の処理目的は理解できる一方で、一つの処理の出力に後続工程まで含めて説明する傾向がある。

| 対象 | その処理の直後の出力 |
|---|---|
| `fetch()` | `Response`オブジェクト |
| `response.json()` | JavaScriptの配列またはオブジェクト |
| JSX生成 | 画面構造 |
| ブラウザ描画 | 実際に表示された画面 |

コード読解では、対象行または関数が直接担当する範囲で止め、後続工程を出力へ含めないことが課題である。

## 今後の重点練習

各行または各関数を、今後も次の形式で確認する。

```text
入力：
その処理が直接受け取るもの

処理：
その行または関数が実際に行うこと

出力：
その処理が直後に返すもの
```

例として、今日の2つの処理は次のように区切る。

| 対象 | 入力 | 処理 | 直後の出力 |
|---|---|---|---|
| `fetch()` | APIのURL | HTTPリクエストを送る。 | `Response`オブジェクト |
| `response.json()` | `Response`本文のJSON | JSONをJavaScriptの値へ変換する。 | JavaScriptの配列またはオブジェクト |
