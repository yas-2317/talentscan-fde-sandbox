## Component・Props・State・Eventの関係

今回確認した基本的な流れは次のとおり。

```text
親Component
↓ Propsを渡す
子Component
↓ Eventが起きる
Stateが変わる
↓
Componentが再実行される
↓
画面表示が変わる
```

| 用語 | 今回確認した役割 |
|---|---|
| Component | 画面を構成する部品。 |
| Props | 親Componentから渡される値。 |
| State | Componentが実行中に覚えている現在値。 |
| Event | クリックや入力など、処理を開始するきっかけ。 |

## 最初に確認したコード

本人が最初に提示したコードは次のとおり。

```tsx
export function MermaidDiagram({ chart }: { chart: string }) {
  const reactId = useId();
  const [svg, setSvg] = useState("");
  const [failed, setFailed] = useState(false);
```

このコードから、Component、Props、Stateを次のように特定した。

| 種類 | コード上の値 | 補足 |
|---|---|---|
| Component | `MermaidDiagram` | JSXを返す画面部品。 |
| Props | `chart` | 親Componentから受け取る。型は`string`。 |
| State | `svg` | 初期値は空文字`""`、更新関数は`setSvg`。 |
| State | `failed` | 初期値は`false`、更新関数は`setFailed`。 |

次の値はStateではない。

```tsx
const reactId = useId();
```

`reactId`は`useId`によって生成される識別用の値であり、`useState`で保持・更新するStateではない。

## Eventの有無

本人は、ファイル内に`onClick`、`onChange`、`onSubmit`などがないと判断した。ファイル全文を確認した結果、この判断は正しかった。

```text
ユーザー操作を受け取るEvent処理
→ なし
```

Client Componentであっても、必ずユーザー操作Eventを持つわけではない。今回の`MermaidDiagram`にはブラウザ側で動く処理があるが、クリックや入力を受け取る処理はない。

## `useEffect`はEventではない

ファイルには次の処理がある。

```tsx
useEffect(() => {
  // Mermaid図を生成する処理
}, [chart, reactId]);
```

`useEffect`は、Componentが画面へ反映された後や、依存する`chart`・`reactId`が変わった後に処理を実行するReactの仕組みである。

```text
onClick・onChange
→ ユーザー操作を直接受け取るEvent処理

useEffect
→ 画面反映後や依存値の変化後に副作用を実行する仕組み
```

今回のファイルでは`useEffect`がMermaidライブラリを読み込み、受け取った`chart`をSVGへ変換する。ユーザー操作によるEventとは区別する。

## Mermaid図が表示されるまで

実ファイルから、Props、State、`useEffect`、表示の関係を次の順番で確認した。

```text
親Componentからchartを受け取る
↓
最初はsvgが空文字、failedがfalse
↓
「図を読み込んでいます…」を表示
↓
useEffectが実行される
↓
mermaidライブラリを動的に読み込む
↓
chartをSVGへ変換する
↓
成功時：setSvg(result.svg)
失敗時：setFailed(true)
↓
Stateが変わる
↓
Componentが再実行される
↓
表示内容が切り替わる
```

表示はStateによって3つに分岐する。

| 条件 | 表示 |
|---|---|
| `failed`が`true` | 「図を表示できませんでした」と元の`chart`を表示する。 |
| `svg`に値がある | 生成されたMermaid図を表示する。 |
| `failed`が`false`かつ`svg`が空 | 「図を読み込んでいます…」を表示する。 |

このファイルではEventでStateが変わるのではなく、`useEffect`内の非同期処理が成功または失敗した結果としてStateが更新される。

## Client Component

ファイル先頭には次の指定がある。

```tsx
"use client";
```

`MermaidDiagram`は`useState`、`useEffect`、`useId`を使うClient Componentである。

ただし、`"use client"`は「必ず`onClick`などのEventがある」という意味ではない。ブラウザ側の機能を使うComponentであることと、ユーザー操作Eventが存在することは別に判断する。

## 理解確認と本人回答

### 理解確認1：Props

**質問：** `MermaidDiagram`が親Componentから受け取るPropsは何か。

**本人回答：** `Props: Chart`

```text

```

これはPropsの役割を誤解したものではなく、大文字・小文字の表記上の修正として扱う。

### 理解確認2：失敗を覚えるState

**質問：** Mermaid図の生成に失敗したことを覚えているStateは何か。

**本人回答：** `State: failed`

**評価：** 正解。

生成に失敗した場合、`setFailed(true)`によって`failed`が`true`になる。

### 理解確認3：`useEffect`とEvent

**質問：** `useEffect`は、ボタンクリックなどのユーザー操作によって発生するEventか。

**本人回答：**

```text
回答：いいえ
理由：Componentが画面に表示されたときや値が変わったときに処理を実行する仕組みのため
```

**評価：** 正解。

ユーザー操作によるEventと、Componentの画面反映後や依存値の変化後に処理する`useEffect`を区別できた。
