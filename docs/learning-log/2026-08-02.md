## メモリ上のデータ加工とDB保存

次のコードは、候補者配列から80点以上の要素を抽出し、新しい配列を作る。

```ts
const passedCandidates = candidates.filter(
  (candidate) => candidate.score >= 80
);
```

ここで行われるのは、実行中のプログラムがメモリ上で扱う配列の加工である。

```text
候補者配列
↓
filterで条件判定
↓
条件に合う候補者だけを含む新しい配列
```

`filter`は条件に合う要素を選ぶが、DBへの書き込みは行わない。そのため、`passedCandidates`が自動的に永続保存されることはない。

DBへ保存するには、配列操作とは別に書き込み処理が必要になる。

```text
データを受け取る
↓
内容を検証する
↓
DBのcreate・insert・updateなどを実行する
↓
保存結果を返す
```

| 処理 | 今回区別した役割 |
|---|---|
| `filter` | メモリ上の配列から、条件に合う要素を残す。 |
| `create`・`insert` | 新しいデータをDBへ保存する代表的な処理。 |
| `update` | DBにある既存データを変更して保存する代表的な処理。 |

ただし、これらの単語が検索結果に出ただけでDB処理とは判断しない。ファイルパスと前後のコードを確認する必要がある。

## 画面表示とDB保存は別

候補者一覧が画面に表示されていても、データの出所は複数考えられる。

```text
ファイル内に直接書かれた配列
JSONやTypeScriptファイルからのimport
APIから取得したデータ
DBから取得したデータ
```

フロントエンドは、どの方法で用意されたデータでも画面へ表示できる。したがって、表示されているという結果だけでは、データがDBに保存されているかを判断できない。

```text
画面に表示されている
≠
DBに保存されていることの証拠
```

## 理解確認と本人回答

### 理解確認1：`filter`とDB保存

**質問：** 次のコードで`passedCandidates`を作った場合、合格候補者は自動的にDBへ保存されるか。

```ts
const passedCandidates = candidates.filter(
  (candidate) => candidate.score >= 80
);
```

**本人回答：**

```text
回答：されない。
理由：filterはDBへの書き込み・保存を実施しないため
```

**評価：** 正解。

配列を絞り込む処理と、DBへ永続保存する処理を区別できた。

### 理解確認2：画面表示と保存状態

**質問：** 候補者一覧が画面へ表示されているだけでは、DB保存済みか判断できないのはなぜか。

**本人回答：**

```text
回答：画面への表示とDBへの保存は別の処理であるため
```

**評価：** 正解。

表示には固定配列、import、API、DB取得結果など複数のデータソースを使えるため、画面だけでは保存先を判定できないと補足した。

### 理解確認3：DB書き込みの検索語

**質問：** 候補者データがDBに保存されているか確認するため、コード上で探すべき処理を2つ挙げる。

**本人回答：**

```text
1：create
2：insert
など
```

**評価：** 概ね正解。

`create`と`insert`は、新しいデータの保存を示す代表的な語である。既存データを変更する`update`も、DB書き込みを探す際の確認対象になる。

## 実コードを確認した理由

本人から次の発言があった。

> 理解確認問題に正解したとしても、実コードは見といた方がいいよね

理解確認では、概念を自分の言葉で説明できるかを確認できる。実コードの探索では、さらに次を確認できる。

```text
処理がどのファイルにあるか
検索語が本当にDB処理を指しているか
何を入力として受け取るか
どこへ保存するか
何を結果として返すか
```

このため、概念理解の後に実リポジトリを検索し、検索結果の意味を確認した。
