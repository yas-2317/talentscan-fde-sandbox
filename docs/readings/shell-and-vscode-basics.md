# Shell & VS Code Basics

## このGuideの使い方

このGuideは、順番に読み切る教材ではなく、ターミナルやVS Codeの操作で迷ったときに戻ってくる常設の参照資料です。

- 初回は最初から最後まで一度通読する（約30分）
- 2回目以降は、目次から必要な章だけを開く
- 「TalentScanを使う10分練習」は、操作に不安が出たときに何度でも繰り返す

このGuideを読んでもLessonの完了数は変わりません。進捗はカリキュラムの必須Lessonだけで判定されます。

## ターミナルとシェルの違い

| 用語 | 正体 | 例 |
|---|---|---|
| ターミナル | 文字の入出力を表示するアプリ（窓） | macOSのTerminal.app、VS Codeの統合ターミナル |
| シェル | 入力されたコマンドを解釈して実行するプログラム | zsh、bash |

ターミナルは「画面」、シェルは「中で動く通訳」です。TalentScanの開発では、VS Codeの統合ターミナル（窓）の中でzsh（通訳）が動いている構成が基本になります。

どのシェルが動いているかは次で確認できます。

```bash
echo $SHELL
```

## プロンプト、コマンド、引数、オプション

シェルが入力を待っている状態を示す表示をプロンプトと呼びます。`%`や`$`で終わる行が出ていれば、次のコマンドを入力できます。

```bash
pnpm dev --port 3001
```

この1行は次の3つに分解できます。

| 部分 | 名前 | 役割 |
|---|---|---|
| `pnpm` | コマンド | 実行するプログラム |
| `dev` | 引数 | プログラムに渡す対象・値 |
| `--port 3001` | オプション | 動作の調整。`-`または`--`で始まる |

エラーメッセージを読むときも、まず「どのコマンドに、何を渡したのか」をこの分解で確認します。

## 絶対パス・相対パス・現在地

シェルには常に「現在地（カレントディレクトリ）」があります。同じコマンドでも現在地が違うと結果が変わるため、迷ったらまず現在地を確認します。

```bash
pwd            # 現在地を表示する
ls             # 現在地のファイル一覧を表示する
cd docs        # 現在地からdocsへ移動する（相対パス）
cd /Users/you/Codex/talentscan-fde-sandbox   # どこからでも同じ場所へ移動する（絶対パス）
cd ..          # 1つ上の階層へ移動する
```

- 絶対パス: `/`から始まる。現在地に関係なく同じ場所を指す
- 相対パス: 現在地を起点に指す。`..`は1つ上、`.`は現在地

`pnpm dev`が「package.jsonが見つからない」と失敗する場合、ほとんどは現在地がプロジェクトの外です。`pwd`で確認してから実行し直します。

## Tab補完、履歴、Ctrl + R

長いパスやコマンドは手で全部打たず、シェルに補完させます。

| 操作 | 効果 |
|---|---|
| `Tab` | ファイル名・コマンド名を補完する。候補が複数なら一覧表示 |
| `↑` / `↓` | 過去に実行したコマンドを順にたどる |
| `Ctrl + R` | 過去のコマンドを文字列で検索する（もう一度押すとさらに遡る） |

補完は入力ミスを防ぐ手段でもあります。`docs/readings/`のような深い階層は、`do`+`Tab`、`re`+`Tab`のように区切りごとに補完するのが確実です。

## 実行中・終了・停止の見分け方

コマンドには「すぐ終わるもの」と「動き続けるもの」があります。

- プロンプトが戻ってきた → コマンドは終了した。次の入力ができる
- プロンプトが戻らない → まだ実行中。`pnpm dev`のような開発サーバーは、止めるまで動き続けるのが正常
- 何も表示されず固まって見える → 実行中か、入力待ちの可能性。まず`Enter`を1回押して反応を見る

`pnpm dev`を実行したターミナルは、サーバーが動いている間は占有されます。別のコマンドを打ちたいときは、新しいターミナルをもう1枚開きます。

## Ctrl + C、q、clear、Ctrl + L

「終わらせたい」「画面を片付けたい」ときの基本操作です。

| 操作 | 効果 | 使う場面 |
|---|---|---|
| `Ctrl + C` | 実行中のコマンドを中断する | `pnpm dev`を止める、暴走したコマンドを止める |
| `q` | ページャー表示を閉じる | `git log`などで画面が`:`表示になったとき |
| `clear` / `Ctrl + L` | 画面表示を消してプロンプトを一番上へ | 出力が多くて見づらいとき |

`clear`は過去の出力を消すだけで、実行中のプロセスには影響しません。一方`Ctrl + C`はプロセスを止めるので、開発サーバーに対して押せば`localhost:3000`は応答しなくなります。

## 標準出力とエラーの見方

コマンドの出力には、正常な結果（標準出力）とエラー（標準エラー出力）が混ざって表示されます。読むときの順番を決めておくと迷いません。

1. 最後の数行を見る。成功・失敗の結論は末尾に出ることが多い
2. `error`、`failed`、`ENOENT`、`command not found`などの単語を探す
3. エラーが長い場合は、一番最初に出たerrorを探す。後続のエラーは連鎖のことが多い

```text
sh: next: command not found
```

このように「コマンドが見つからない」と出たら、依存関係が未インストール（`pnpm install`前）か、現在地が違うかをまず疑います。

## VS CodeのExplorer、Editor、Panel

VS Codeの画面は大きく3つの領域で構成されます。

| 領域 | 場所 | 役割 |
|---|---|---|
| Explorer | 左サイドバー | プロジェクトのファイルツリーを表示・選択する |
| Editor | 中央 | ファイルを開いて編集する。タブで複数開ける |
| Panel | 下部 | 統合ターミナル、Problems、出力などを表示する |

「コードを探す・読むのはExplorerとEditor」「実行と結果確認はPanel」と役割を分けて覚えると、視線の移動先が決まります。

## Cmd + PとCmd + Shift + F

ファイル数が増えると、Explorerのツリーを目で追うより検索が速くなります。

| 操作 | 効果 | 使う場面 |
|---|---|---|
| `Cmd + P` | ファイル名で検索して開く | 開きたいファイル名が分かっているとき |
| `Cmd + Shift + F` | プロジェクト全体を文字列で検索する | 「この文言はどのファイルにあるか」を探すとき |

例えば画面に表示されている「教材」という文字がどこで定義されているかを探すには、`Cmd + Shift + F`で「教材」を検索します。画面の文字列から実装ファイルを逆引きするこの手順は、FDEのコード読解で最もよく使う動きです。

## 保存、自動保存、未保存状態

編集がブラウザに反映されない原因の多くは「保存していない」ことです。

- タブのファイル名の右に「●」が付いていれば未保存
- `Cmd + S`で保存する
- File → Auto Saveを有効にすると、一定時間ごとに自動保存される

`pnpm dev`の開発サーバーは、ファイルが保存された瞬間に画面を更新します。「変更したのに変わらない」ときは、まずタブの「●」を確認します。

## 統合ターミナル、Problems、Source Control

Panelとサイドバーには、コードの状態を教えてくれる場所が3つあります。

| 場所 | 開き方 | 分かること |
|---|---|---|
| 統合ターミナル | **Ctrl + バッククォート** | コマンドの実行結果、開発サーバーのログ |
| Problems | Panelのタブ | TypeScriptやESLintが検出したエラー・警告の一覧 |
| Source Control | 左サイドバーの分岐アイコン | どのファイルを変更したか、変更前後の差分 |

Problemsに赤いエラーが出ている状態は、buildが失敗する可能性が高い状態です。commit前にProblemsとSource Controlの差分を確認する習慣をつけます。

## TalentScanを使う10分練習

このリポジトリで、ここまでの操作を通しで練習します。

1. VS CodeでTalentScanのフォルダを開く
2. **Ctrl + バッククォート**で統合ターミナルを開き、`pwd`で現在地を確認する
3. `ls`で`package.json`があることを確認する
4. `pnpm dev`を実行し、プロンプトが戻らないこと（実行中）を確認する
5. ブラウザで`http://localhost:3000/learning`を開く
6. `Cmd + P`で`page.tsx`を検索し、`app/learning/page.tsx`を開く
7. `Cmd + Shift + F`で「FDE Roadmap」を検索し、表示文字列の定義場所を確認する
8. ターミナルに戻り、`Ctrl + C`でサーバーを止める
9. ブラウザを再読み込みし、応答しなくなることを確認する
10. もう一度`pnpm dev`で起動し、画面が戻ることを確認する

一連の流れを、手が止まらなくなるまで繰り返します。

## 成功時に見るもの

「動いている」と判断するための確認先を決めておきます。

- ターミナル: `Ready in ...ms`や`Local: http://localhost:3000`の表示
- ブラウザ: 対象URLが表示され、開発者ツールのConsoleに赤いエラーがない
- VS Code: Problemsタブにエラーが0件

なんとなく動いていそう、ではなく、この3点を毎回同じ順番で見るのが再現性のある確認方法です。

## 失敗したときに見る場所

エラーが出たら、当てずっぽうに直す前に次の順で場所を特定します。

1. ターミナルの最後の出力。コマンド自体が失敗していないか
2. ブラウザの画面。Next.jsのエラーオーバーレイが出ていないか
3. ブラウザ開発者ツールのConsoleとNetwork。どのリクエストが失敗したか
4. VS CodeのProblems。型エラーやlintエラーが残っていないか

どの層で失敗しているかが分かれば、直す場所は絞れます。切り分けた結果と復旧手順は、Troubleshootingログに記録します。

## よくある間違い

| 症状 | よくある原因 | 確認方法 |
|---|---|---|
| `command not found` | 依存関係が未インストール、またはコマンド名の打ち間違い | `pnpm install`を実行したか。スペルをTab補完で確認 |
| `package.jsonが見つからない` | 現在地がプロジェクトの外 | `pwd`と`ls`で現在地を確認 |
| 変更が画面に反映されない | ファイルが未保存 | タブの「●」を確認して`Cmd + S` |
| `localhost:3000`につながらない | 開発サーバーが起動していない、または止めた | `pnpm dev`のターミナルの表示を確認 |
| ターミナルが反応しない | 前のコマンドが実行中、またはページャー表示中 | プロンプトの有無を確認。`q`または`Ctrl + C` |
| 別のポートで起動した | 3000番が使用中で3001番などに変わった | ターミナルの`Local:`表示のURLを開く |

同じ間違いを2回したら、この表に自分の言葉で1行足すつもりで読み返してください。
